Every agent session needs its own isolated slice of your repository so parallel agents don't overwrite each other's work. AO handles this through a workspace plugin that creates and cleans up the working directory for each session automatically. Two workspace modes ship out of the box, and you can build your own for specialized setups.

## Comparing workspace modes

| Feature | worktree | clone |
|---|---|---|
| Disk usage | Low (shared `.git` object database) | High (full copy per session) |
| Session creation speed | Fast | Slower (initial clone overhead) |
| Build tooling compatibility | Most tools | All tools |
| Fresh `node_modules` per session | No | Yes |
| Supported platforms | macOS, Linux, Windows | macOS, Linux, Windows |

## Choosing a workspace mode

**Default: `worktree`.** Git worktrees share the underlying `.git` object database, so even dozens of parallel agents use minimal extra disk space. This is the right choice for nearly everyone.

**Choose `clone`** in these situations:

- Your build tooling walks the `.git` directory and gets confused by the worktree layout (rare, but it happens with some language toolchains).
- You want every agent to start with a completely fresh `node_modules`, `cargo/target`, or similar dependency directory.
- You're deliberately pointing different agent sessions at different remotes for experimentation.
