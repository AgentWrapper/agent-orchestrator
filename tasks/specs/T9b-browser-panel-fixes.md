# T9b — Correções do painel de browser (achados da verificação de segurança)

## Objective
Fix the seven verified defects in the T9 browser-panel implementation. All paths below are under `/Users/paulo/Projects/agent-orchestrator/frontend`.

## Fixes (all mandatory)

1. **ACL brick (app-breaking).** `src-tauri/build.rs` declares `AppManifest::commands` with only 3 commands, which flips `has_app_acl = true` and makes Tauri reject EVERY app command not explicitly granted — the main window has zero app-command grants, so all IPC (daemon_*, keybindings_*, browser_*, …) is rejected at runtime. Fix: declare **every** `#[tauri::command]` registered in `src-tauri/src/lib.rs` in `AppManifest::commands` (keep the list in one place, e.g. a shared const or build-script list with a test asserting it matches `generate_handler!`), and grant the corresponding autogenerated `allow-*` permissions in `capabilities/main.json` for ALL commands EXCEPT keep `capabilities/browser-panel.json` limited to exactly the existing 3. Add a Rust test asserting: every command name in the invoke handler appears in the autogenerated permissions AND is granted to main-window (parse `gen/schemas/capabilities.json` after build like the existing capability test does).
2. **`browser_capture` blocks the main thread.** It is a sync command executed inline on the IPC/main thread, then waits `recv_timeout` for a completion only the main run loop can deliver (5s freeze + empty result). Fix: make it `#[tauri::command(async)]` (or `async fn` + `spawn_blocking` for the wait); audit ALL `browser_*` commands for the same pattern — any command that calls `*_blocking` helpers must not run inline on the main thread. Add a code comment citing the contract from tasks/specs/T9-browser-panel.md header.
3. **`mirror://` unscoped.** `src-tauri/src/browser/mirror.rs::protocol_handler` serves frames for any viewId to any caller. Fix: (a) validate the host with `is_browser_label`-style checks; (b) only serve when the requesting context is the main window — use the handler's context (`ctx.webview_label() == "main"`; reject otherwise with 403); (c) add `Access-Control-Allow-Origin` restricted to the renderer origins `tauri://localhost` and `http://tauri.localhost` so the renderer canvas is NOT tainted (this also fixes the canvas.captureStream SecurityError hang risk).
4. **canvasMirror hang path.** In `src/renderer/hooks/useBrowserView.ts`, `canvasMirror` can leave a promise pending forever if `captureStream` throws inside `img.onload`. Fix: wrap the onload body in try/catch that rejects/falls back to `frameMirror`; set `img.crossOrigin = "anonymous"` (works with fix 3c).
5. **Dead URL normalizer.** `src/renderer/lib/browser-url.ts` is never imported. Fix: call `normalizeBrowserURL` (omnibox/search fallback) in `useBrowserView.ts` before `browser.navigate` (the ~line-511 call site), so raw input like `example.com` or search terms work as under Electron. Keep tests green; add one hook-level or unit test covering the wiring (import + transformation applied).
6. **Vacuous test.** `validate_caller_accepts_a_matching_label_and_view_id` in `src-tauri/src/browser/annotate.rs` asserts string equality without calling `validate_caller`. Rewrite to call the real function for match, mismatch, and non-browser-label cases.
7. **Shortcut-forward keylogging surface.** The annotate bundle forwards every keydown (including plain typed characters) from remote pages to the main renderer. Fix in `src/browser-annotate/main.ts`: only forward events with a chord-relevant modifier combination (ctrl/meta, or the specific Backquote chord pattern used by `shared/shortcuts.ts`), never bare keys/text; rebuild `src-tauri/src/browser/annotate-bundle.js` via `npm run build:browser-annotate` so source and artifact stay in sync. Also create `src/browser-annotate/README.md` (referenced by `src-tauri/src/browser/host.rs` but missing) with the build-step rationale, or fix the reference to point at vite.config.ts.
8. **Document deviation (no code change):** initialization_script runs in the page main world (Electron used an isolated preload) — remote pages can invoke the 3 allowed commands for their own view. Add a `SECURITY` comment block in `annotate.rs` stating the accepted residual risk and the mitigations (label validation, 3-command capability, modifier-gated forwarding).
