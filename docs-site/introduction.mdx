Agent Orchestrator (AO) is an orchestration layer that runs AI coding agents in parallel — each in its own isolated git worktree, terminal session, and branch — while keeping every PR, CI result, and review comment visible from a single dashboard. Instead of babysitting one agent at a time, you delegate a queue of well-scoped issues and AO keeps the fleet moving, routing CI failures and review feedback back to the session that owns the branch.

## What AO Does for You

AO handles the mechanical work of running and supervising agents so you can focus on what only a human can do: picking the right issues, reviewing the output, and deciding when to merge.

| AO handles | You still handle |
|---|---|
| Creating isolated worktrees per session | Choosing well-scoped issues |
| Launching and monitoring agent processes | Reviewing code and agent behavior |
| Routing CI failures and review comments back to agents | Deciding when to merge |
| Tracking PR, CI, and review status across all sessions | Setting repo-specific rules and expectations |
| Cleaning up merged sessions and stale worktrees | Escalating edge cases AO can't resolve |

## When to Use AO

AO works best when you have a backlog of issues that each have a clear finish line. Good candidates include:

- **Failing tests** — a broken test suite with a clear expected outcome
- **Small features** — narrowly scoped additions with obvious acceptance criteria
- **Review follow-ups** — a reviewer requested changes; let an agent address the comments
- **Migrations** — deterministic transformations across many files
- **Documentation updates** — targeted rewrites or additions to docs pages
- **Focused refactors** — rename, extract, or restructure with a well-defined scope

Avoid vague tasks like "improve auth" or "clean up the app." Every worker session needs a task with a visible finish line.

## How a Session Moves

AO turns a GitHub issue into a merged pull request through a supervised lifecycle:

```
issue → ao spawn → worktree + agent → pull request → CI/review loop → merge → cleanup
```

The dashboard shows this as a Kanban board. Each session card carries the agent name, branch, PR link, CI status, and live activity state. You see what needs your attention and ignore the rest.

## Plugin Architecture

AO is built entirely from plugins. The default setup works out of the box for GitHub workflows. Every slot is swappable when your environment is different.

| Plugin slot | What it controls | Default |
|---|---|---|
| Agent | Which AI coding tool writes changes | Claude Code |
| Runtime | How agent processes run | tmux |
| Workspace | Where code is checked out | git worktree |
| Tracker | Where issues come from | GitHub |
| SCM | How PRs, CI, and reviews are read | GitHub |
| Notifier | Where AO sends updates | Desktop notifications |
| Terminal | How you attach to running sessions | iTerm2 |
